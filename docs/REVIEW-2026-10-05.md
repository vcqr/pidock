# PiDock 项目审查报告

日期：2026-10-05 · 范围：全仓（Rust ~3.9k 行 / host TS ~4k 行 / Vue ~12k 行）
方式：静态代码审查 + 跨模块协议一致性核对，未执行构建、未修改任何文件

---

## 总体评价

架构设计是有想法的：stdio JSONL 协议 + ts-rs 导出 TS 绑定、persist/ephemeral 事件分层、
内容寻址附件、compaction 重同步、Kafka/Redis 双管道可切换——这些决策在 README/DESIGN 里
都有清晰理由，M1→M6 的推进节奏也扎实。

但当前状态是**功能先行、防护滞后**。三条底线同时缺失：

1. **多租户授权**：鉴权（authentication）调用点零遗漏，授权（authorization）在 3 条关键
   路径上完全缺失 → 任意登录用户可控制他人机器、删除他人会话历史。
2. **崩溃兜底**：host 进程无 uncaughtException/EPIPE 兜底，Rust 侧无重启/看门狗 →
   一次会话异常 = 整个应用失去 AI 能力，且不会自愈。
3. **工程化门禁**：无 CI、无前端测试、无 lint（脚本指向不存在的目标）、Docker 构建绕过
   `Cargo.lock` → 声称的 "e2e 20/20" 没有自动执行点。

**结论：在 P0 修完前，不建议把 server 部署到任何可被外网访问的环境。**

### 稳定性

| # | 问题 | 位置 |
|---|---|---|
| P0-7 | **host 无进程级异常兜底**。Node/Bun 对 unhandledRejection 默认退出进程。`prompt().finally(() => tracked.drain())` 内抛错（如 `JSON.stringify` 循环引用，自定义工具/MCP 结果很常见）→ 全部会话一起死 | `main.ts:100-126`、`pool.ts:581-584`、`1323/1335/1349`、`map.ts:79` |

| P0-9 | **pi-host 崩溃后永不重启**。tokio `Child::id()` 在未被 reap 前恒为 `Some`，全仓无 `wait()`/`try_wait()` → `spawn()` 永远走 "already running"，应用彻底失去 AI 能力直到手动重启 | `host.rs:35-41` |
| P0-10 | **`Supervisor::kill()` 同锁重入死锁**。`MutexGuard` 作用域到函数末尾，第 250 行再次 `self.inner.lock()` → 永久阻塞 → 退出时 `process::exit(0)` 永不执行。**lib.rs 注释里那句 "webview teardown can hang on Windows" 很可能就是在掩盖这个真死锁** | `host.rs:229-253` |
| P0-11 | **scheduler 锁序反转（ABBA）**。`unregister_job` 持 `sched_ids` 等 `sched`；`register_current`/`ensure_started` 持 `sched` 等 `sched_ids` → 并发保存+停用即死锁，自动化功能静默整体瘫痪 | `scheduler.rs:296-313`、`249-268`、`272-291` |
| P0-12 | **定时任务 `in_flight` 泄漏**。`execute_run` 失败分支不清理 `in_flight` 也不走 `finalize` → 失败一次后该任务永久"运行中"，只能重启应用恢复 | `scheduler.rs:693-705`、`411-452` |

## P1 · 重要（精选 41 项：server 12 / 桌面 10 / host 10 / 前端 9）

**服务端**
- `CorsLayer::permissive()` + 服务端从不读 `Authorization: Bearer`（`fake-desktop.ts` 发的 header 是死代码）；token 全走 query/body `main.rs:406`
- `/health` 不做任何依赖探测（Mongo 挂了、ingest 挂了都返回 200）；`s3.rs:148` 写了 `health_probe()` 但零调用 `main.rs:34-36`
- 无优雅关闭：无 `with_graceful_shutdown`/SIGTERM → WS 断连不走 `machine_offline`，Redis 标记要等 90s TTL `main.rs:409-412`
- ingest 一次性失败即永久停摆，外层无重试 supervisor `ingest.rs:26-33`
- 幂等索引是 `(session_id, seq)`，协议与 README 声明的是 `(session_id, seq, kind)`——spec 与实现真实偏差 `ingest.rs:27-30`
- Redis Streams 模式永不 XACK + 每次启动换新 consumer 名 → PEL 消息永久卡死；compose 里 Redis 还关了持久化 `pipeline.rs:150-212`、`docker-compose.yml:57`
- 附件 presign 用 UNSIGNED-PAYLOAD，从不校验上传内容真等于声称的 sha256；`insert_one` 结果被忽略 → 内容寻址保证为空 + 可抢注 sha256 使他人永久 409 `main.rs:57-83`
- 认证端点无限速，argon2（~19MiB/次）在请求线程同步执行 → CPU/内存型 DoS + 无限开户 `auth.rs:106-154`
- 每个 web 连接独占一条 Redis PubSub 连接，无并发上限 `gateway.rs:148-158`
- WS 读循环内 await Kafka produce（5s 超时）→ 心跳饥饿，机器被误判离线 `gateway.rs:105-112`
- Docker 未 `COPY Cargo.lock` 且无 `--locked` → 开发机锁定版本 ≠ 生产镜像版本 `server.Dockerfile:12-17`
- `COPY apps/web/dist` 依赖本机先跑过 web build（dist 被 gitignore），clone 后首次构建必然失败 `server.Dockerfile:16`

**桌面端**
- access token 15min TTL，但只在建连时刷新一次 → 长连接 15 分钟后所有附件上传 401，且因 tracing 未初始化而静默失败 `sync.rs:339/368-372`
- 同步泵头阻塞：`select!` 分支内直接 await 最长 180s 的 host 命令 → 心跳停发（TTL 90s）、事件通道积压丢弃 `sync.rs:468-496`
- 无半开连接检测：无 ping/pong、无读超时 → 休眠/静默断链后桌面端永远认为在线 `sync.rs:373`
- 附件 PUT 无 timeout/重试/完整性校验；从不计算本地 sha256，只用信封声明值命名上传 `sync.rs:228-233`
- backoff 三处写法各异，两处无上限（u64 溢出），无 jitter `sync.rs:356/378/518`
- CSP 显式关闭（`"csp": null`）+ 自定义命令无 ACL → 任何 XSS 可调用 `host_request` 任意 method、`sync_configure` 改 server_url 提交明文密码 `tauri.conf.json:24-26`
- `reveal_path` 无路径校验直传 `explorer`，Windows 下对 exe/bat/lnk 会直接执行 `lib.rs:59-66`
- refresh_token 明文落盘（非原子写）、access token 进 WS URL、允许 `http://` server_url `sync.rs:26-32/68-75/368-372`
- 定时任务默认 `permission_mode="full"`，无人值守任务默认拿到完全自动批准 `scheduler.rs:42-44`
- **`tracing` 从未初始化**：`sync.rs` 全部 8 处日志是空操作；`host.rs`/`scheduler.rs` 用 `eprintln!`，release 又是 `windows_subsystem="windows"` → 最脆弱的同步链路完全不可观测

**host**
- 每事件调用 `getEntries()`（SDK 内部每次 `filter` 全量数组）→ 5000 条目会话 × 10000 delta = O(n²)，长会话后期明显卡顿 `pool.ts:1270`、`1216-1217`
- 截断用 `String.slice`（UTF-16 码元）切，阈值语义是 BYTES → 中文场景实际是 3 倍；且会切断代理对，`serde_json` 拒收 lone surrogate → Rust 侧整帧丢弃 `map.ts:38/44`、`pool.ts:1327/1339/1354`
- 每次 edit/write 全量同步重写整个快照 JSON（含 base64，可达数十 MB）→ 50 次 edit ≈ GB 级同步写，全程阻塞 `pool.ts:1070`、`912-934`
- `scanTreeMeta` 同步 stat 2 万文件，每次 bash 前后各一遍，全局阻塞 `pool.ts:972-1005`、`1322/1345`
- `bashPreScans` 以 sessionId 为键 → 并发 bash 互相踩踏，误判"新建文件"后 `revertFiles` 会**删文件** `pool.ts:1008-1039`、`1145-1153`
- 工具审批无超时（AskUserQuestion 有完整超时机制，审批没有）→ 用户不点则回合永久挂起 `pool.ts:607-620`
- 全部配置/注册表写入非原子 + 并发 read-modify-write → 崩溃即 JSON 截断损坏，注册表丢失 = 历史会话"凭空消失" `config.ts:30-32`、`pool.ts:173-185`
- auth.json 无 `0600` 权限；`providerSetKey` 后的 `modelRuntime()` 刷新是空操作（缓存命中）`config.ts:173-184`
- 附件目录无 GC/配额/原子写/校验，同步阻塞；`pruneSnapshots` 不覆盖 attachments `map.ts:25-48`
- 同步 `inflateRawSync` 解压炸弹；`skillsInstall` 解压后无体积上限 `attachments.ts:106`、`config.ts:402-435`

**前端**
- 零虚拟滚动 + 流式期间每个 delta 全量 `reduce` 会话文本 + 每秒 `nowTick` 触发整个 ChatView 重渲染 `ChatView.vue:481-489`、`371-383`
- markdown 链接点击会让 Tauri WebView 直接导航离开应用（无 `target=_blank`、无 shell.open 外跳）`MdContent.vue:39-52`
- 消息去重靠"文本相等" → 连发两次"继续"会误确认，另一条永久停在 pending `store.ts:193-196`、`495-497`
- snapshot 合并只比长度不比 seq → 乱序快照可覆盖正确内容 `store.ts:275-289`
- 流式条目可能永久卡 `streaming:true`（abort/崩溃时）→ 闪烁光标不停 `store.ts:144-156`
- 思考级别枚举两处不一致（Composer 5 档 vs SettingsView 7 档）→ 设置 `xhigh` 后输入卡回退显示"中" `Composer.vue:244-250`、`SettingsView.vue:313`
- `DataBus.request` 返回 `any`，全库 53 处 `any`，`protocol` 已定义 `Method` 常量却未接入签名 `databus.ts:14`
- DiffView 主线程 O(n·m) LCS，可分配百万级二维数组 → UI 冻结数秒 `DiffView.vue:19-38`
- 弹窗无焦点陷阱/Esc/dialog 语义；侧栏全 `div+@click` 键盘不可达

## 做得对的地方（保持）

- 协议分层设计（delta/snapshot/complete）与内容寻址附件，方向正确
